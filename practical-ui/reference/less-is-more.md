# Less is more

## Remove unnecessary information
Every element competes with every other. Remove repetition (e.g. a course name repeated in every chapter title → make it a subheading), filler words and intro phrases, and progressively disclose secondary information.

## Remove unnecessary styles
Decorative lines, colours, backgrounds, icons and animations that convey nothing add load and can be misread as meaningful (random list colours, a blue underlined non-link heading, a decorative icon that looks like a button, competing loud icons). Trend styles (glassmorphism, neumorphism) age badly and make hierarchy and contrast hard — experiment only if usability and accessibility survive.

## Not all links need underlines
Plain text links: colour + underline (safest). Components that already read as interactive (nav menus, tabs, cards = image + text in a raised box) can drop the link treatment.

## Progressive disclosure
Show what the current task needs; reveal the rest on demand. Slightly more interaction cost, much less cognitive load. Use descriptive disclosure labels ("Benefits of a custom domain"), not "Show more". Forms: reveal a field only when an opt-in checkbox is ticked (e.g. "Receive updates via text message" → Mobile number*).

## Minimal ≠ simple
Removing too much makes UIs vague: unlabelled icons/filters/nav, barely visible selected states, hidden share/save actions, low-contrast icons. Keep important actions visible, labelled, and high-contrast.

## Smallest screen first
Designing mobile-first forces prioritisation; desktop doesn't need to be "filled".

## Break up choices (Hick's Law)
1. **Remove** choices that don't earn their place (e.g. drop name/company from a newsletter form → email only).
2. **Group/categorise** (article list → category tabs).
3. **Split into steps** (multi-step forms, multi-level navigation).
4. **Recommend** (popular items, suggested searches).
