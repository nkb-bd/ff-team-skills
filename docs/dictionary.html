Vocabulary

The concepts the skills are built out of.

Detector
One parallel review lens in pre-merge-review — accessibility, async races, permissions, and four others — each scanning the diff for its own class of defect.
Dispatch
Choosing the right skill from what the user wants. Start from the intent ("fix this bug"), not from the skill list.
Gate
An explicit approval checkpoint between phases. Work does not advance until the gate is cleared — ceremony that scales with the tier.
Orchestrator
A composite skill that sequences other skills and owns the phase order. new-feature is the one orchestrator; everything else is a specialist.
Seam
The real call site a failing test must exercise. The correct-seam check in tdd rejects a test that passes without touching the actual bug.
Specialist
A single-purpose skill you can call directly for standalone work, or that the orchestrator invokes as one step.
Tier
The 5-step size classification (trivial → breaking) that decides how much ceremony a change gets. A typo skips everything; a breaking change hardens every gate.

Orchestrators

Sequence the work and own the phase order.

$new-featureguide ↗
End-to-end workflow for a new plugin feature. Six phases with approval gates: triage → align → plan → spec → build → review → ship. Decides which specialists to invoke and when.
$rigorous-coding-workflowguide ↗
The principles layer under new-feature — plan before executing, use subagents for context hygiene, capture lessons, verify before done, push for elegance.

Plan & align

Sharpen the plan before any code is written.

$design-an-interfaceguide ↗
Generate three-plus radically different interface designs for a module via parallel sub-agents, each with a divergent constraint. Compare, pick, record.
$grill-meguide ↗
A relentless plan interview that resolves every branch of the decision tree until you and the agent share one understanding. Pure alignment, no doc updates.
$grill-with-docsguide ↗
Grilling that stress-tests a plan against the project's domain model — CONTEXT.md, ADRs — and updates the docs inline as decisions crystallise.

Build

Write the change — and stay grounded while doing it.

$bug-fixguide ↗
The canonical bug workflow. Fix mode: reproduce → minimise → hypothesise → instrument → fix → regression-test. Find mode: a plugin-wide discovery sweep with a Finder → Verifier → Feedback loop.
$source-driven-developmentguide ↗
Ground every framework claim in the vendored source or official docs before asserting it. Anything you can't verify gets tagged UNVERIFIED: so it's never silently asserted.
$tddguide ↗
Test-driven development — red-green-refactor with the correct-seam check: the failing test must exercise the bug pattern at the real call site.
$zoom-outguide ↗
A higher-level map of an unfamiliar code area for when you're lost mid-task.

Review & quality

Judge code before it merges — and deepen it after.

$doubt-driven-developmentguide ↗
Adversarial fresh-context review for irreversible decisions: CLAIM → EXTRACT → DOUBT → RECONCILE → STOP, spawning a clean-context skeptic whose job is to refute.
$explain-thisguide ↗
Teaches a file, feature, or PR to mastery — a running coverage checklist, five-whys on every decision, and eli5 / eli14 / intern depth levels. Quizzes are opt-in.
$improve-codebase-architectureguide ↗
Finds deepening and refactoring opportunities informed by CONTEXT.md domain language and ADRs. The post-merge home for a mid-feature refactor itch.
$plugin-auditguide ↗
A deep WordPress-plugin audit — security, optimization, dead code, UI-to-DB traceability — producing evidence-backed findings and a severity-ranked remediation backlog.
$pre-merge-reviewguide ↗
The canonical pre-merge review. Full: seven parallel detectors plus sequential pattern passes. Light: pattern passes only, for tiny diffs. Re-runnable — clears resolved findings.

Ship & setup

Package the work and wire up the repo.

$agents-onboardingguide ↗
Create or refresh AGENTS.md onboarding docs so coding agents behave consistently in a repo.
$pr-descriptorguide ↗
A why-first PR description built from the actual git evidence, filling the repo's PR template.
$setup-code-review-graphguide ↗
Wire the code-review-graph MCP server into a repo — .mcp.json, the CLAUDE.md block, and the seed build — so the codebase can be queried as a structural graph.
