Flow overview

Build primary

new-feature

End-to-end composite workflow. Picks an intensity tier, runs gated phases, then routes build, review, and ship steps.

Trivial: skip skill, just commit.
Small: Phase 5 light.
Medium: Plan, build, light review.
Large: full workflow.
Breaking: full workflow plus plugin audit.
Source: new-feature/SKILL.md
Fix and find default

bug-fix

Single bug-handling skill with two modes: fix a known issue, or find issues through a verifier-backed sweep.

fix: reproduce, minimise, instrument, fix, test.
find: Finder, Verifier, calibration report.
graph: callers, dependents, tests, impact radius when available.
Source: bug-fix/SKILL.md
Review gate

pre-merge-review

Single pre-merge gate. Full mode combines parallel detectors with sequential pattern passes; light mode is for tiny diffs.

full: 7 detectors plus 9 pattern passes.
light: sequential passes only.
graph: review context and impact radius before detector fan-out.
Source: pre-merge-review/SKILL.md

Inside new-feature

Phase 0: Triage to Phase 1: Align with grill-with-docs to Phase 2: Plan with OpenSpec and design-an-interface to Phase 3: Spec to Phase 4: Build with tdd and bug-fix to Phase 5: Review to Phase 6: Ship

Each phase has an explicit approval gate. Trivial changes skip the workflow; small changes run the light review path.

Phase 0: Triage

Read project rulesLoad CLAUDE.md and AGENTS.md first; they override defaults for branch, hooks, commits, stack, and test commands.
Find upstream artifactLook for issue, PRD, OpenSpec change, or tracer-bullet task before asking discovery questions.
Pick tierTrivial skips the skill; Small runs light review; Medium runs plan/build/light review; Large runs full flow; Breaking adds mandatory align and plugin audit.
Use graph if availabledetect_changes helps score risk and pick the right tier before broad grep.

Phase 1: Align

Invoke grill-with-docsConfirm vocabulary against project docs and ADRs.
Create/update CONTEXT.mdCapture the project vocabulary, canonical nouns, constraints, and agreed problem language during alignment.
Read/update docs/adr/*.mdUse existing ADRs as constraints; create a new ADR only when the decision is load-bearing.
Resolve nounChoose the canonical feature name and the user/problem it serves.
Define smallest valueAgree on the smallest version that is still worth shipping.
GateShow one-sentence problem statement plus canonical noun; wait for approval.

Phase 2: Plan

Name changeUse issue-<n>-<noun> when linked to an issue, otherwise kebab-case noun.
Create OpenSpec folderRun openspec new change <name> to create openspec/changes/<name>/.
Create proposal.mdWrite Why, What Changes, Capabilities, and Impact; mark breaking changes explicitly.
Large tier designUse design-an-interface for 3+ shapes, compare, choose one, then carry the chosen design into design.md.
GateShow proposal and selected design; wait for approval.

Phase 3: Spec

Create specs/<capability>/spec.mdWrite requirements with SHALL/MUST language.
ScenariosEach scenario uses WHEN/THEN and should map to a future test.
Create design.mdCapture context, goals, decisions, alternatives, risks, migration, and open questions.
Create tasks.mdWrite small session-sized checklist items grouped by setup, core implementation, tests, docs, and ship.
ValidateRun openspec validate <name> --strict.
GateShow spec and tasks; wait for approval.

Phase 4: Build

TDD loopUse tdd: Red failing test, Green minimal code, Refactor only after green.
WordPress safetySanitize and unslash input, escape output, verify nonce before capability, prepare SQL, protect REST routes.
Extension seamsAdd meaningful filters/actions where Pro or third parties need to short-circuit, extend, or observe.
Repo styleFollow the target stack: FluentPlayer uses Vue 3; FluentForm uses Vue 2; read project docs to confirm.
ClassmapAfter adding PHP classes, run composer autoload refresh and verify classmap when the repo needs it.
Update tasks.mdMark OpenSpec task checkboxes as milestones complete, commit intentionally, never push without explicit consent.
Bug during buildSwitch into bug-fix and build a feedback loop before guessing.

Phase 5: Review

LightFor Tier <= Medium, run pre-merge-review light with sequential pattern passes only.
DeepFor Large and Breaking, run full pre-merge-review: seven detectors plus sequential passes.
Create review reportWrite a re-runnable report under hosted review storage, repo .review/<branch>.md, or openspec/changes/<name>/PRE-MERGE-REVIEW.md.
ResolveAddress every Blocking finding, re-run review, and track cleared findings.
GateShow the report; wait for approval before push.

Phase 6: Ship

Create PR descriptionUse pr-descriptor from the real git diff and repo PR template.
Issue closeUse Closes #n or Fixes #n when Phase 0 found an upstream issue.
ConsentAsk before pushing or running gh pr create; approval is not permanent.
Archive OpenSpecAfter merge, run openspec archive <change-name> so accepted requirements move into long-lived specs/.
Post-merge docsUse plugin-audit quarterly; update CONTEXT.md again if shipped work introduced new domain terms.

Never do

No mega-stepDo not collapse the workflow; the gates are where cheap corrections happen.
No stale reviewValidate review criteria before using them for important work.
No mid-feature rewriteDo not refactor the whole codebase while shipping a feature; defer architecture lift.
No hidden pushNever push, open PR, or assume consent without asking.

Files created or updated by the process

CLAUDE.md / AGENTS.mdRead first when present. They define project-specific commands, stack, branch, hook prefix, style, and safety rules.
CONTEXT.mdCreated or updated by alignment work when project vocabulary, domain nouns, or decisions need to be captured.
docs/adr/*.mdRead during alignment/design. New ADRs are created only for load-bearing decisions, schema choices, public API design, or debated architecture.
openspec/changes/<name>/proposal.mdCreated in Phase 2 with Why, What Changes, Capabilities, and Impact.
openspec/changes/<name>/design.mdCreated in Phase 3 with context, goals, decisions, alternatives, risks, migration, and open questions.
openspec/changes/<name>/tasks.mdCreated in Phase 3 and updated during Phase 4 as work is completed.
openspec/changes/<name>/specs/<capability>/spec.mdCreated in Phase 3 with requirements and scenarios that map to tests.
.review/<branch>.mdFallback pre-merge review report when hosted review storage is unavailable.
openspec/changes/<name>/PRE-MERGE-REVIEW.mdReview report location when the branch is tracked by OpenSpec.
bug-discovery-report.mdCreated by bug-fix find, not by normal feature work.
specs/ archived outputAfter merge, openspec archive <name> moves accepted changes into long-lived specs.

Inside pre-merge-review

7 specialized detectors

AccessibilityKeyboard navigation, screen readers, focus, ARIA.
Async racesStale responses, retry races, cancel races.
UI to backend wiringHardcoded stubs, CTA mismatch, dropped context.
Permissions and capabilitiesUI gates mapped to policy capabilities.
Backward compatibilityPayload renames, default flips, shape drift.
Error handling UXBlank-on-error, stuck spinners, hidden failures.
Performance and data integrityN+1 queries, unbounded work, non-atomic state.

9 sequential pattern passes

Pass ABreaking changes
Pass BRegression risk
Pass CCode quality
Pass DWordPress and PHP patterns
Pass EJavaScript patterns
Pass FVue 2 patterns
Pass GPerformance quick-check
Pass HBackward compatibility
Pass IState machine and adversarial inputs

code-review-graph usage

When a repo is indexed, graph tools are the first stop for structural questions. They do not replace reading the diff or source files.

new-featureUses graph during triage, alignment, spec/design, build, and review phases.
bug-fixUses graph for changed flows, callers, importers, impact radius, existing tests, and regression-test seams.
pre-merge-reviewUses graph for review context, affected flows, callers/importers, tests, and impact radius before detector fan-out.
plugin-auditUses graph for module maps, UI-to-handler traces, handler-to-database traces, dead-code candidates, and risky-path coverage.
cross-plugin-coordinationUses graph for Free/Pro contract surface inventory when both repos are indexed.

Archived skills

Old skill Replacement Why
