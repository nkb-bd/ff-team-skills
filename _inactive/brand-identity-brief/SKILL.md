# Brand Identity Brief

A brand isn't a logo. It's the set of decisions that make every future
design choice obvious. This skill produces the smallest viable brief
that prevents drift, without pretending to be a 60-page brand book.

## Step 1 — Anchor the brand in the strategy (not in mood)

Before any visual decisions, restate (from positioning + JTBD work):

1. The buyer (one segment, named)
2. The primary job (one statement)
3. The wedge (the empty-quadrant value)
4. The anti-positioning (who/what this is NOT)

If any of these are missing, stop and do `[[positioning]]` and
`[[jtbd]]` first.

## Step 2 — Pick the 3 brand attributes (not 8)

Force exactly **3** adjectives that the brand should embody. They must
be:

- **Mutually distinct** (don't pick "trustworthy + reliable + credible")
- **Sacrificial** — choosing them implies *not* being other things
- **Demonstrable** through design choices, not just claimed

Examples for a hyperlocal trust-driven directory:
- *Verifiable* (every claim has visible evidence)
- *Local* (rooted in the place, not generic)
- *Warm* (community-driven, not corporate)

Bad examples:
- *Innovative, scalable, user-friendly* (every product claims these)
- *Premium, modern, clean* (mood board, not strategy)

## Step 3 — Voice and tone

**Voice** = constant. **Tone** = adjusts to context.

Voice rubric (pick one end of each axis):

| Axis | Pick |
|---|---|
| Formal ↔ Conversational | |
| Reserved ↔ Enthusiastic | |
| Serious ↔ Playful | |
| Authority ↔ Peer | |

Then write **5 short example sentences** the brand would say:
- Welcome / homepage hero
- Confirmation after listing submission
- Empty search result
- Error / something went wrong
- Trust badge tooltip

These 5 are the calibration set. Future copy is judged against them.

**Language strategy**: if the audience speaks multiple languages
(Bengali + English + diaspora-English + Sylheti dialect), name the
**primary** language and the rules for the others (transliterated?
toggle? mixed code-switch where natural?). Don't punt.

## Step 4 — Naming criteria (if naming is open)

Don't pick the name yet — write the criteria:

- Pronounceability in primary language(s)
- Domain availability (.com + local TLD)
- Cultural / religious sensitivities
- Trademark availability in target geography
- Resists negative association ("Lyft" → "lift", "Uber" → "above")
- ≤3 syllables, preferably

Then brainstorm 20, kill 17, test the remaining 3 with target users.

## Step 5 — Visual direction (direction, not designs)

Don't choose final colors / fonts / logo. Choose **the direction** so
the designer can converge:

- **Color stance**: warm vs cool, saturated vs muted, mono vs polychrome,
  cultural connotations (red = wedding/auspicious in BD, white = funeral
  context, green = Islamic, etc.)
- **Type stance**: serif (authority, editorial) vs sans (modern,
  utilitarian) vs grotesque (technical) vs humanist (warm). Must
  support primary language script (Bangla type ≠ Latin type — confirm
  the typeface has a usable Bangla cut).
- **Photo / illustration stance**: real photography (authenticity,
  hard to scale) vs illustration (consistency, can feel generic) vs
  documentary (best for trust-driven local products) vs none (UI-first)
- **Iconography stance**: pictographic vs abstract vs none

For each: give 1-2 sentence rationale, not a Pinterest board.

## Step 6 — 3 brand "do / don't" rules

Forcing brevity prevents the rules from being ignored. Examples:

- DO show real Sylhet, by name. DON'T use generic "South Asian city"
  stock imagery.
- DO let community moderators sign their work with real names.
  DON'T hide moderation behind a faceless "team."
- DO use Bangla typography as a first-class citizen. DON'T treat
  Bengali as a transliteration of English.

## Output

A 1-page brief with:

1. Strategy anchor (4 lines from Step 1)
2. 3 brand attributes
3. Voice rubric + 5 calibration sentences
4. Language strategy
5. Naming criteria (if applicable)
6. Visual direction (color / type / image / icon — direction only)
7. 3 do/don't rules

Pass this to the designer. Iterate the brief, not the deliverable.
